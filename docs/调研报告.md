# Code Agent 调研报告

> 调研时间：2026-10 · 调研范围：GitHub 开源项目、小林coding DevFlow AI、业界商业产品与中文社区
> 结论服务于本项目的定位与架构设计（见 设计文档.md）

## 一、GitHub 主流开源 Code Agent

| 项目 | 主循环范式 | 多 Agent | 框架依赖 | 上下文管理 | 现状 |
|---|---|---|---|---|---|
| **OpenHands** | ReAct（Action/Observation/Executor 类型化 + 事件溯源） | 微代理 | 自研 SDK（Pydantic） | Condenser 压缩 + Skill 触发 | 活跃，SWE-bench Verified 77.6% |
| **SWE-agent** | 模板驱动 ReAct，YAML 全配置 | 无（批量并行） | 自研 | history_processors 管道 | 维护模式 → mini-swe-agent（**100 行** 达 65%） |
| **Aider** | 结对聊天（人工确认） | 无 | 自研 | Repo Map（tree-sitter + PageRank 图排名，默认 1k token） | 活跃 |
| **gpt-pilot** | 多角色流水线状态机（Spec→Arch→Task→Code→Review 含打回） | 是 | 自研 | 任务级上下文过滤 | 已停止维护（曾有供应链投毒，仅作架构参考） |
| **Devika** | 中央控制器 + 状态机 + Socket.IO 状态可视化 | 是（Planner/Researcher/Coder/...） | 自研 | 相关性选择性注入 | 已归档 |
| **MetaGPT** | 角色 Observe→Think→Act + 发布/订阅（SOP 编码进提示词） | 是 | 完全自研 | 每 Role 独立 Memory | 活跃 |
| **AutoCodeRover** | 两阶段 ReAct：AST 结构感知检索 → 补丁 | 无 | 自研 | AST 搜索工具收窄上下文 | 活跃（每任务 < $0.7） |
| **Claude Code** | `while(true)` + function calling（"One loop & Bash is all you need"） | Task 子代理 + hooks | **零框架** | prompt caching + PreCompact + 子代理干净上下文 | 商业产品 |

**共性规律（对本项目最重要的结论）**：
1. **没有一个主流实现用 LangChain/LangGraph**，全部自研编排；
2. 内核都收敛为「while 循环 + 工具调用回填消息列表」，差异在工具面设计（ACI）、上下文管理与编排层；
3. 上下文管理的三个流派：压缩（Condenser）、结构化检索收窄（Repo Map / AST 搜索）、隔离（子代理干净上下文）；
4. 工具输出截断与友好报错是 ACI 的核心——工具是给模型看的接口，不是给人用的。

## 二、小林coding DevFlow AI（对标项目）

- 定位：**面向研发协作场景的多智能体助手**，三大场景：分析 Issue / 审查 PR / 排查 CI 失败；
- 技术栈：Python 3.12 + FastAPI + **LangChain/LangGraph** + MCP + Postgres/PGVector + Redis/MinIO + Docker Compose；
- 编排：Planner → Researcher → Reporter + **Critic 反思机制**（LangGraph 状态机驱动）；
- 四大面试考察点（官方教程目录推断）：任务调度、证据检索、记忆、效果评测；
- 性质：付费训练营项目（2026-10 上线，源码不公开，GitHub 无公开仓库）——本项目为其**场景定位的自主复现**，
  编排内核自研而非 LangGraph，并补充了沙箱、事件溯源、离线评测等工程件。

## 三、业界商业产品与垂直场景

| 产品 | 产品化的核心工作流 |
|---|---|
| Claude Code | 终端通用 agent：CLAUDE.md 团队规范 + hooks 确定性门禁 + subagent 上下文隔离 |
| Cursor | AST 分块 + 自研 embedding + Merkle 树增量索引的代码库语义 RAG |
| Copilot coding agent | **issue → PR 全自动**（GitHub Actions 沙箱 + MCP 外接工具） |
| CodeRabbit | PR 自动评审：ast-grep 做 AST 级结构分析而非纯文本 diff |
| Diffblue Cover | Java 单测批量生成（字节码分析 + RL，保证可编译可跑） |
| 美团/阿里实践 | AI 代码评审（集团级）、单测生成（"AI 编程的安全网"）、31 万行存量重构 |

**企业需求热度排序（国内语境）**：
1. **AI 代码评审（CR）**——CR 积压重、标准不齐，阿里/美团均有集团级实践，最明确的付费场景；
2. **单测生成**——覆盖率考核 + 存量代码缺测试；
3. **存量/遗留系统改造**——逆向文档、迁移（差异化亮点）；
4. 需求→代码、CI 修复、PR 摘要——多为附属能力。

**共同技术要素**：代码库 RAG（AST 分块 + embedding + 增量索引）、AST 解析（tree-sitter/ast-grep）、
工具调用与 agent loop、沙箱、上下文工程（规则文件/hooks/subagent）、**评测 eval**（正成为选型核心门槛）。

## 四、对本项目的指导结论

1. **场景选型**：以 PR 评审（= CR，需求最旺）为主打，Issue 分析与 CI 排障为伴生场景（同一套「证据检索 → 结论 → 质检」管线），三者共享一套编排引擎——引擎的复用性本身就是卖点；
2. **编排内核自研**（对齐主流做法），但语义与 LangGraph 对齐（节点/条件边/反思回路），迁移成本可控；
3. **证据优先**：结论必须挂 `file:line` 级证据（EVIDENCE 行协议），Critic 以证据充分性做质检——这是 DevFlow AI 的核心设计，也是对抗幻觉的正确姿势；
4. **评测先行**：`devlens eval` 用固定案例 + 结构断言打分，接真实模型后同一套断言度量效果；
5. **安全边界**：路径收敛 + 命令白名单 + 输出截断，是所有落地产品的共识工程件。
